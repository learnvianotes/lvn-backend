# Admin sign-in code and the activity log

Backward compatible: new fields and operations. Existing queries keep working. When `ADMIN_MFA_REQUIRED` is on (the production default), an admin or staff access token that has not finished MFA is rejected with `ADMIN_MFA_REQUIRED` on admin operations.

## Sign-in

`signIn`, `signInWithGoogle`, `oauthExchange`, `signUp` and `refreshSession` now return:

- `mfaRequired: Boolean!` — true when this session still needs a code
- `mfaFactors: [MfaFactorType!]!` — `EMAIL_OTP` when a code can be sent, otherwise empty

The session is still returned. Use its access token for the two mutations below. A normal account has `mfaRequired: false`.

## Mutations

`startMfaChallenge(factor: MfaFactorType!): MfaChallengePayload!`

- `factor`: `EMAIL_OTP` (sends the code), `TOTP` and `WEBAUTHN` are reserved and return `VALIDATION`
- payload: `challengeId`, `factor`, `expiresAt`, `userErrors`
- five sends an hour per account, plus a per-network cap (`RATE_LIMITED`, `retryAfter`)

`verifyMfaChallenge(challengeId: UUID!, code: String!): MfaVerifyPayload!`

- payload: `session` (new access token; refresh token rotates) or `userErrors`
- wrong code: `VALIDATION`. Five wrong attempts burn the code. Expired and reused codes are `VALIDATION`
- the new access token's `amr` includes `otp`. Admin MFA lasts 12 hours, then the code is required again. Sign-out ends it immediately

`setMfaOptIn(optIn: Boolean!): OkPayload!` stores a preference. No screen calls it yet. The next sign-in applies it.

`adminRecoverMfa(input: { userId, reason }): OkPayload!` — a platform admin who has already passed MFA. Clears the other account's lockout for 2 hours. `VALIDATION` when recovering yourself.

## Queries

`mfaStatus: MfaStatus!` — `required`, `satisfied`, `verifiedAt`, `factors`, `allowedFactors`. Does not itself require MFA.

`adminActivity(filter: { actorId, action, targetType, from, to }, cursor, limit): AdminActivityConnection!`

`adminActivitySummary(from, to): AdminActivitySummary!` — `total`, `byAction`, `byDay`.

Both require a platform admin with a valid MFA.

## Errors

- `ADMIN_MFA_REQUIRED` — admin operation, session has not finished MFA (or it is older than 12 hours)
- `MFA_REQUIRED` — the same guard used outside admin operations
- `RATE_LIMITED` — too many codes or too many checks
- `FORBIDDEN` — not an admin. Unchanged for a normal account
