# Teachers: connections, sharing with connections, publications, the Skills tab (Phase 3, P3b-2)

- Date: 2026-10-12
- Package: `@lvn/contracts` 0.21.0 (`teacher.editProfile`; `ConnectionChanged.by`)
- Spec: §4.1, §4.2, §5; ADR-0012, ADR-0013, ADR-0014, ADR-0015, ADR-0044
- Breaking: no. `createNote` now accepts the other kinds that it refused before.

## What changes for clients

**Connections** (teachers, ADR-0013):

| Field | What |
| --- | --- |
| `User.relation.connected`, `pendingConnection { direction requestId }` | INCOMING: they asked; OUTGOING: you asked |
| `relation.viewerCan.requestConnection / respondToConnection / removeConnection` | Show the buttons from these |
| `requestConnection`, `removeConnection` | `input: { userId }` |
| `respondToConnectionRequest(input: { requestId, accept })` | Returns the person who asked |
| `withdrawConnectionRequest(input: { requestId })` | Returns the person who was asked |
| `myConnections`, `myConnectionRequests` | The lists |

- Refusals: "Teachers connect with other teachers." and, when they already asked you, "They already asked to connect
  with you: accept their request instead." (CONFLICT).
- Notifications: `CONNECTION`, with `data.kind` `REQUESTED` (path `/u/<who asked>`) or `ACCEPTED` (path
  `/u/<who accepted>`).

**Sharing:**
- A teacher shares directly with another teacher only once they are connected. Otherwise the refusal is "Teachers
  share with other teachers once they are connected."
- `setNoteSharedWithConnections(input: { noteId, shared })`, teachers only. The note becomes SHARED with every
  connection, now and as connections come and go.
- `Note.sharedWithConnections` (owner only) and `NoteShare.source` (`DIRECT | CONNECTIONS`) show how each person got
  access. Stopping removes only CONNECTIONS rows.

**Publications:** `createNote(kind:)` takes `NOTE` and `PROJECT` from anyone, and `BLOG` and `POST` from teachers.
Otherwise the refusal is "Blogs and posts are for teachers." Posts and projects start with `allowForks: false`.
Profiles list them under their kind (`User.publicNotes(kind:)`).

**Skills tab:** `User.teacherProfile { headline bio skills { kind name detail source } }` is public for teachers and
null otherwise. `updateTeacherProfile(input: { headline, bio, skills })` replaces the whole tab: a headline of up to
120 characters, a bio of up to 2,000, and up to 60 items in the order given.

## Behind it

- `users.Connection` (one row per pair) and `users.ConnectionRequest`. A block removes both.
- `users.TeacherProfile` and `users.TeacherSkill` (source MANUAL).
- `notes.Note.sharedWithConnections` and `notes.NoteShare.source`. Notes handles `ConnectionChanged` and adds or
  removes CONNECTIONS rows.
- The `PEOPLE` facade gains `connectionIds` and `connected`.
