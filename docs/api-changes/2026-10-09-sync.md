# Offline sync for devices (Phase 2, P2f)

- Date: 2026-10-09
- Package: `@lvn/contracts` unchanged; GraphQL only
- Spec: §13.2
- Breaking: no

## Push

`syncPush(ops: [SyncOpInput!]!)` applies a device's outbox in order (at most 100): `CREATE_NOTE` (with the id the
device gave the note, a UUIDv7, its title and first cards), `UPDATE_NOTE` (title and card operations exactly as
`updateNoteDraft`, so the §13.2 conflict rules are the same), `TRASH_NOTE`, `RESTORE_NOTE`. Each operation carries a
`clientOpId`; sending it again returns the first answer (kept 30 days; a re-sent `CREATE_NOTE` of the device's own note
is always APPLIED).

Per operation: `APPLIED`, `REJECTED` (with `code` and `message`: it will never apply, so the app lists it as needing
attention) or `RETRY` (rate limited or a server error: this and every later operation should be sent again later).
`cardResults` and `conflictVersionId` as in `updateNoteDraft`.

## Pull

`syncPull(since, after, first)`: notes changed since the cursor of the last completed sync (`since`, read with a
2-second overlap so late commits are not missed) or after the previous page (`after`), oldest change first, 1–50
(default 20) — the account's own notes (trashed ones too) and notes shared with it. Each comes with all its cards (the
draft for owners and editors, the published version for readers). `liveNoteIds` lists every note the account may keep;
devices remove the others. Keep `cursor` for the next sync while `hasMore` is false.

## Other changes

- `CreateNoteInput.id`: a device-made id for notes written offline (CONFLICT if taken).
- Sharing a note marks it changed, so the devices of the person it is shared with pick it up.
- `notes.SyncOpLog` (migration `20261009050000_sync_ops`), pruned nightly (`prune-sync-log`, 03:50 UTC).
