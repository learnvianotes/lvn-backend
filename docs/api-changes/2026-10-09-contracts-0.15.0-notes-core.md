# @lvn/contracts 0.15.0 — the notes core (Phase 2, P2a)

- Date: 2026-10-09
- Package: `@lvn/contracts` 0.14.0 → 0.15.0 (unpublished)
- Spec: §4.1–§4.5, §5, §6.2, §6.3, §13.2
- Breaking: no (additions only)

## What and why

Notes become real: subjects and topics, folders, tags, notes, cards of all sixteen types, drafts, versions, the trash.
Web (P2b) and mobile (P2f) build their editors on this. Sharing, visibility changes and forking are P2c; media cards
(image, video, audio, file) are refused until P2c attaches uploads to notes.

## `@lvn/contracts/validation` (new subpath)

| Export | Use |
| --- | --- |
| `CARD_CONTENT`, `parseCardContent(type, content)`, `CARD_LIMITS`, `MEDIA_CARD_TYPES` | The content of each card type. Rich text is a subset of Tiptap/ProseMirror JSON (`docSchema`, `inlineSchema`, `markSchema`): paragraphs, nested lists (5 levels), text with bold, italic, underline, strike, code, highlight, sub/superscript and links (`http`, `https`, `mailto` only). `NoteVersionKind` gains `DRAFT`: the draft as it was before a version was restored.

## GraphQL (notes subgraph)

Queries: `note(id)` (null when the viewer may not read it, exactly as for a missing id; anonymous visitors get PUBLIC
published notes), `myNotes(filter, first, after)`, `myFolders`, `myTags`, `subjects`, `subject(slug)`,
`findTopics(query, subjectId)`.

Mutations: `createNote`, `updateNoteDraft`, `publishNote`, `restoreNoteVersion`, `deleteNote` (trash),
`restoreNote`, `deleteNoteForever`, `createFolder`, `updateFolder`, `deleteFolder`, `renameTag`, `deleteTag`,
`proposeTopic`. All take one `input` and return a payload with `userErrors` (§6.2).

`Note` loads in two steps (§6.3): metadata, `viewerAccess` (OWNER, EDITOR, READER), `viewerCan`, `outline`, then
`cards(first, after)` — the draft for the owner and share editors, the published version for readers. Lists are Relay
connections, at most 100 per page.

`updateNoteDraft` is the autosave and the future sync push: title, folder, tags and topics are last-writer-wins; card
operations (`UPSERT`, `MOVE`, `DELETE`, with the `baseRevision` the client last saw) follow §13.2 per card —
`APPLIED`, `APPLIED_WITH_CONFLICT` (the other device's text kept as a CONFLICT version, returned as
`conflictVersion`) or `REJECTED` (a delete of a card changed elsewhere). Card ids are client-made UUIDs. One invalid
card fails the whole save.

The users subgraph now resolves `User` references (a note's `owner`, a version's `createdBy`): public fields for
anyone, viewer-only fields only for the viewer.

## Authorization

The §5 matrix in `@lvn/contracts/domain` (`can`), applied by the API on every query and mutation: owner and share
EDITOR edit the draft (EDITOR only while the note is SHARED or PUBLIC); only the owner publishes, deletes, restores and
organises (folders, tags); publishing needs a verified account. Readers other than editors need a published version.
The same predicate as a database filter (`visibleNotesWhere`) is tested equal to the per-note decision on every
combination of visibility, publication, trash and share role.
