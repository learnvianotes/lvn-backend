# Terms version 2026-11-03

- Date: 2026-11-03
- Package: `@lvn/contracts` unchanged; no schema change
- Spec: §15.2 ("re-prompt on material change"); [2026-10-09 accepting the terms again](2026-10-09-accept-terms-again.md)
- Breaking: no for the schema. The accepted value changes.

`Query.termsVersion` is now `2026-11-03` (was `2026-10-08`), matching lvn-web's `features/legal/documents.ts` after
the legal text was finalised. `signUp`, `completeRegistration` and `acceptTerms` accept only `2026-11-03`; anything
else is VALIDATION on `acceptedTermsVersion` / `version`, as before.

## Existing accounts

Accounts whose latest acceptance is `2026-10-08` now read `viewer.termsAccepted: false`. Nothing in the API is gated on
it: sign-in, `refreshSession` and every other operation work as before. Web and mobile show their accept dialog
(`TermsGate`) on signed-in pages until `acceptTerms(input: { version: "2026-11-03" })` succeeds; the account / settings
page stays open.

## Migration

None. Clients send `Query.termsVersion` back, so they pick up the new value without a release. A form loaded before
the deploy gets one VALIDATION answer on submit; reloading fetches the new version.
