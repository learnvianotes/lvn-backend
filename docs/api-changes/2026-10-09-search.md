# Search (Phase 2, P2e)

- Date: 2026-10-09
- Package: `@lvn/contracts` unchanged; GraphQL only
- Spec: §10.4 (Postgres provider of Phases 2–3), §9.1 `search` queue, §5
- Breaking: no

## GraphQL (notes subgraph)

`search(query: String!, scopes: [SearchScope!], first: Int): SearchResults!` — signed in or not.

| Group | What |
| --- | --- |
| `notes: [NoteSearchHit { note, snippet }]` | The published version's title, topics and words, English word forms (heap/heaps), the last word as a prefix (results while typing), title typos (trigram). Only notes the viewer may read: public ones for everyone, plus their own and shared ones. `snippet` wraps each match in U+E000 … U+E001 |
| `people: [User]` | Handles starting with, or names containing, the query. Only people past the digital-consent age; minors never appear |
| `topics: [Topic]` | Curated topics, and the viewer's own proposals |

`scopes` limits the groups (default all), `first` is per group (1–20, default 5), queries are at most 100 characters
(VALIDATION) and a query without letters or digits finds nothing.

## Indexing

`notes.NoteSearchDocument` (migration `20261009040000_note_search`) holds each note's published version as a
`tsvector` (title A, topics B, words C) with a trigram index on titles. `publishNote` and topic changes of a published
note queue `notes.search/index-note`; apps/worker runs it and a nightly `reindex-all` (04:15 UTC). Visibility is never
stored there: queries filter by the read predicate, so a note leaving PUBLIC leaves public search at once.

The API now connects to Redis for queues too (it only enqueues).
