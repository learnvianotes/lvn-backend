# @lvn/contracts 0.4.0 — teacher follows and connections

- Date: 2026-10-08
- Package: `@lvn/contracts` 0.3.0 → 0.4.0 (unpublished)
- ADR: 0013
- Breaking: no for callers; `NoteRelation` gains a member, so exhaustive `switch`es over it need a new case

## What changed

| Area | Change |
| --- | --- |
| `Action` | `USER_FOLLOW`, `USER_UNFOLLOW`, `USER_REQUEST_CONNECTION`, `USER_RESPOND_TO_CONNECTION`, `USER_REMOVE_CONNECTION`. |
| `Resource` | New `user` kind (`targetId`, `targetGlobalRole`, `following`, `connected`, `pendingConnection`, `blocked`). `note` gains optional `shareTarget` (`USER` with connection / co-teaching facts, `CONNECTIONS`, `GROUP`, `CLASSROOM`). |
| `NoteFacts` / readers | Optional `sharedToActorAsConnection`; new `CONNECTION_SHARE` relation reads SHARED and PUBLIC notes. |
| `can()` | Follow/connect are teacher-to-teacher, never self, never across a block; connection requests need a verified email and nothing pending. A teacher shares a note with another teacher only when connected or co-teaching; only teachers share with all connections. |
| Events | `UserFollowed`, `UserUnfollowed`, `ConnectionRequested`, `ConnectionChanged` (version 1). |
| GraphQL skeleton | `ShareNoteInput.toConnections`. |

## Migration

None. The backend passes `shareTarget` and the connection facts once `users` stores follows and connections (Phase 3).
