# ADR-0029: Mobile UI — Uniwind + react-native-reusables + our own brand components, animated with Reanimated 4

- Status: Accepted (owner, 2026-10-08)
- Date: 2026-10-08
- Spec sections: §2 (Mobile: "React Native Paper or Tamagui"), §12.2, §13.3
- Amends: §2 Mobile row (UI kit)

## Context

The owner wants the mobile app to feel like the LearnViaNotes UI board (docs/design/ui-reference.md): lavender-tinted
backgrounds, white 16 px cards, one indigo accent, pill chips, tinted icon tiles, a tab bar with a raised centre "+",
dark night-sky hero cards, and fast, smooth micro-animations — not stock Material Design. The app is Expo SDK 57 /
React Native 0.86 (New Architecture), built locally (ADR-0008); the web app is Next.js 15 with Tailwind 4 + shadcn/ui.

Research (2026-10-08; versions and dates from the npm registry and GitHub):

| Option | Verdict |
| --- | --- |
| **Uniwind** (Tailwind 4 for React Native, build-time styles; MIT, v1.12, explicit Expo 57 support) | Same Tailwind 4 CSS-first tokens as the web; fastest styling path. Young project — pin versions. |
| **react-native-reusables** (shadcn/ui for React Native; MIT; components copied into the repo) | Same component names, variants and token names as lvn-web's shadcn; accessible primitives; we own the code. |
| HeroUI Native (Apache-2.0, v1, on Uniwind) | Closest out-of-the-box look; a dependency with its own token names; open performance issues. **Fallback.** |
| NativeWind v5 | Same idea as Uniwind, still a release candidate; v4 uses Tailwind 3. Swap-in option if Uniwind stalls. |
| Tamagui (v2, v3 in beta) | Own token system that does not map to Tailwind; Android regressions in v2; v3 changes syntax again. |
| React Native Paper | Material 3 — the look the owner wants to avoid. |
| gluestack-ui v5, Unistyles 3, Restyle, UI Kitten, Dripsy | Generic look, no components, stagnant, unproven revival, or dormant. |

## Decision

- **Styling:** Uniwind (free edition), Tailwind 4 `className` on React Native, versions pinned exactly.
- **Components:** react-native-reusables (Uniwind variant), copied into `components/ui/` — buttons, inputs, dialogs,
  sheets, tabs, switches, selects — restyled to the brand.
- **Brand components we build:** `HeroCard` (night-sky), `TabBar` with the raised "+", `IconTile`, `Chip`, `RhythmRing`
  (ADR-0030), `NoteCard`, `StatTile`. Any kit would need these custom.
- **One set of design tokens for web and mobile:** a single `tokens.json` (colours light/dark, radius, spacing, type
  scale) generates lvn-web's `globals.css` and lvn-mobile's Uniwind theme, using shadcn's token names (`--primary`,
  `--card`, `--radius`, …) on both — lvn-web's tokens are renamed to match in the same change. Dark-mode accent stays
  `#818CF8` (indigo `#4F46E5` fails AA on dark backgrounds).
- **Animation and feel:**
  - Reanimated 4 at Expo's pinned version: CSS-style transitions for state changes (chip selection, tab indicator,
    theme), keyframes for loops (skeleton shimmer, ring pulse), layout animations for lists, worklets only for gestures
    and scroll (collapsing hero, swipe cards). `useReducedMotion` everywhere.
  - react-native-gesture-handler at Expo's pin; v3 after an SDK upgrade.
  - expo-haptics: selection ticks for chips and tabs, a light impact on "+"; Android uses the platform haptics API.
  - Lottie for designer-made one-shot illustrations (empty states, celebrations). Rive only if a mascot is wanted.
  - Not Moti (stale; Reanimated 4's CSS-style API covers it).
- **Budgets** (from ADR-0030): tap-to-feedback < 100 ms, transitions 150–400 ms, no dropped frames on a low-end
  Android phone in release builds.

## Risks

- Uniwind and react-native-reusables are young and small-team: versions pinned; components already live in our repo;
  NativeWind v5 uses the same Tailwind 4 CSS if Uniwind must be replaced.
- Free Uniwind cannot drive animations through `className`: animations use Reanimated style props.
- Native files are regenerated by `expo prebuild`: native settings only through config plugins (ADR-0008).

## Consequences

- One design language and one token source across web and mobile; components are ours to shape to the boards.
- Phase 1 starts the mobile design system (tokens, primitives, brand components) before the first real screens.
