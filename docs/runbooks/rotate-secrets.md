# Rotate secrets

When: a secret may have leaked (in a log, a commit, a screenshot, a departing person's laptop), or on the yearly
rotation. gitleaks runs over every repository in Phase 9 and in CI; a finding there starts this runbook.

Every secret is generated by Terraform and stored in Secrets Manager (`modules/secrets`, `<name>/<SECRET>`) or, on the
local environment, in the VM's Terraform state. Nothing is typed by hand, so rotating is replacing the generator.

| Secret | Effect of rotating | How |
| --- | --- | --- |
| `JWT_PRIVATE_KEY` | Every access token stops verifying; people refresh silently (refresh tokens are in the database, not signed) | `terraform apply -replace=tls_private_key.jwt`, then deploy |
| `DATABASE_URL` (password) | Brief connection errors until tasks restart | RDS: `aws rds modify-db-instance --master-user-password`. Local: `-replace=random_password.postgres`. Then deploy |
| `REDIS_URL` (auth token) | Sessions' revocation lists and queues reconnect; waiting jobs stay | ElastiCache: modify the auth token with `--auth-token-update-strategy ROTATE`, then deploy, then `SET`. Local: `-replace=random_password.redis` |
| `CODE_HMAC_SECRET` | Email codes and links already sent stop working; people ask again | `-replace=random_password.code_hmac` |
| `AI_KEYS_SECRET` | Saved AI provider keys can no longer be read: admins enter them again in AI settings | `-replace=random_password.ai_keys`; tell platform admins first |
| `REVALIDATE_SECRET` | None visible | `-replace=random_password.revalidate` |
| `TYPESENSE_API_KEY` | Search is off until the API restarts with the new key | `-replace=random_password.typesense` |
| S3 keys (local) | None visible | `-replace=random_password.s3_access_key -replace=random_password.s3_secret_key` |
| Firebase, GitHub App, OAuth client secrets, SES, Sentry | Sign-in with that provider fails until the new value is in place | Rotate in the provider's console, put the new value in Secrets Manager or `envs/<env>/.env`, deploy |

Steps:

1. Rotate with `infra/terraform/run.sh <env> apply -replace=<resource>`. Locally, run `deploy-local.sh`, which applies
   in the VM.
2. Deploy (`infra/scripts/deploy.sh <env>`) so tasks pick the new value up; ECS reads secrets at task start.
3. Check: `pnpm smoke <url>`, a sign-in on web and phone.
4. If the old value leaked, search the logs (Loki, or `vm.sh ssh 'docker logs …'`) for its use after the leak, and
   follow `leakage-report.md` if anyone used it.
