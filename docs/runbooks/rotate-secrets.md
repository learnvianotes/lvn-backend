# Rotate secrets

When: a secret may have leaked (in a log, a commit, a screenshot, a departing person's laptop), or on the yearly
rotation. gitleaks runs over every repository in Phase 9 and in CI; a finding there starts this runbook.

On Lightsail (ADR-0096) every secret is a GitHub environment secret (`LVN_*`, docs/runbooks/lightsail.md), made by
`infra/lightsail/new-secrets.sh` and written to the VM by each deploy. On the local environment they are generated by
Terraform and live in the VM's state. Nothing is typed by hand.

Where the table says `-replace=…`, that is the local environment; on Lightsail it is a new value from
`new-secrets.sh` in the matching `LVN_<NAME>` secret.

| Secret | Effect of rotating | How |
| --- | --- | --- |
| `JWT_PRIVATE_KEY` | Every access token stops verifying; people refresh silently (refresh tokens are in the database, not signed) | Lightsail: a new pair from `new-secrets.sh` into `LVN_JWT_PRIVATE_KEY` and `LVN_JWT_PUBLIC_KEY`, then deploy. Local: `terraform apply -replace=tls_private_key.jwt` |
| `DATABASE_URL` (password) | Brief connection errors until the api and worker restart | Lightsail: on the VM, `docker compose exec postgres psql -U lvn -c "alter user lvn password '<new>'"`, then the new value in `LVN_POSTGRES_PASSWORD` and deploy. Local: `-replace=random_password.postgres` |
| `REDIS_URL` (password) | Sessions' revocation lists and queues reconnect; waiting jobs stay | Lightsail: the new value in `LVN_REDIS_PASSWORD`, then deploy (Redis restarts with it). Local: `-replace=random_password.redis` |
| `CODE_HMAC_SECRET` | Email codes and links already sent stop working; people ask again | `-replace=random_password.code_hmac` |
| `AI_KEYS_SECRET` | Saved AI provider keys can no longer be read: admins enter them again in AI settings | `-replace=random_password.ai_keys`; tell platform admins first |
| `REVALIDATE_SECRET` | None visible | `-replace=random_password.revalidate` |
| `SCANNER_SECRET` | Uploads stay pending until both hosts have the new value | `openssl rand -hex 32` into `LVN_BACKEND_EXTRA_ENV` and `/opt/lvn-scan/scanner.env`, then redeploy the API and restart the scanner (`docs/ops/scanner-host.md`) |
| `TYPESENSE_API_KEY` | Search is off until the API restarts with the new key | `-replace=random_password.typesense` |
| S3 keys (local) | None visible | `-replace=random_password.s3_access_key -replace=random_password.s3_secret_key` |
| R2 keys (`LVN_R2_*`), `LVN_RESEND_API_KEY`, `LVN_GHCR_TOKEN` | Files, email or the next deploy's image pull fail until the new value is in place | Make a new token in Cloudflare, Resend or GitHub, put it in the GitHub environment, deploy, then revoke the old one |
| Firebase, GitHub App, OAuth client secrets, Sentry | Sign-in with that provider fails until the new value is in place | Rotate in the provider's console, put the new value in the GitHub environment (`LVN_BACKEND_EXTRA_ENV` for those without their own secret) or `envs/local/.env`, deploy |

Steps:

1. Lightsail: change the GitHub environment secret, then re-run the environment's last deploy (GitHub → Actions →
   deploy → Re-run), which rewrites `/opt/lvn/env` and restarts what changed. Local: `deploy-local.sh` with
   `-replace=<resource>` applied in the VM (`vm.sh ssh 'cd lvn/infra/terraform && ./run.sh local apply -replace=…'`).
2. Wait for the deploy's readiness check to pass.
3. Check: `pnpm smoke <url>`, a sign-in on web and phone.
4. If the old value leaked, search the logs (Loki, or `vm.sh ssh 'docker logs …'`) for its use after the leak, and
   follow `leakage-report.md` if anyone used it.
